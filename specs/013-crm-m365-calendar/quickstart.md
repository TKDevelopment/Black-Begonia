## 4. Microsoft 365 sandbox smoke matrix

Perform these through the real sandbox provider and browser, recording observed Graph/CRM IDs and times in a private test log without tokens or customer data:

| Scenario | Expected result |
|---|---|
| Connect as admin; try as staff | Admin selects one scoped calendar; staff can view status but cannot connect, change, disconnect, refresh, or resolve conflicts. |
| Seed one of each CRM source type | Correct title/date/type in CRM and Microsoft; no customer invitation; workshop draft stays CRM-only until publication. |
| Convert a lead and reschedule a workshop | One active project/replacement item; obsolete mirrors retired; no duplicate after retry. |
| Partial, full, waived installment | CRM status and current modal amounts are accurate; no amount or method appears in Microsoft. |
| Add/edit/cancel/delete Graph-only all-day, timed, multi-day, and recurring events | Correct occurrences and exceptions in Month/List; a returned nonprivate `isCancelled` item is inactive Canceled, while a tombstone or completed-scan absence removes it. |
| Cancel a private Graph-only occurrence | It remains `Private event` with date/time only if returned; no canceled or Microsoft source/type label, subject, or location is exposed. |
| Mark Graph-only event private | Only `Private event` and date/time appear in full CRM views/modal, without a separate source/type/status label; dashboard has at most a day indicator; no private subject/location/body is stored. |
| Edit a CRM-created event in Microsoft | CRM source unchanged; one admin conflict; admin restores current CRM projection; no duplicate mirror. |
| Force throttling, outage, authorization/RBAC failure | CRM dates remain visible; safe status and last successful sync shown; retry respects provider delay. |
| Disconnect and reconnect same calendar | Existing Microsoft mirrors remain but stop updating while disconnected; warning appears; reconnection reuses associations without duplicates. |
| Open a distant month outside the capped tracked set | Month loads via bounded on-demand import; Microsoft items show loading or are explicitly stale until a complete scan succeeds, then show the current occurrences without stale-month overwrite. |
| Keep 12 distinct nonadjacent months recently requested, then open a 13th | Current and adjacent months remain scheduled, the least-recently-requested other month leaves scheduled polling, and reopening it requests a fresh scan. |
| Request too many new months | The 25th distinct request from one user in a rolling hour, or a request when three distinct on-demand scans are pending, returns a safe retry time; CRM dates remain visible. |
| Delay or fail a distant-month import | After two minutes the loading indicator becomes a delayed or failed message with Retry; Microsoft cache remains stale until a complete scan succeeds. A retry reuses pending work or starts a new run after failure. |
| Interrupt immediate `requestMonth` dispatch | The SQL request remains queued without any SQL-side HTTP call; the named scheduled worker picks it up, and no duplicate import is created. |

Measure the spec outcomes with a representative 200-item month: dashboard response within three seconds; at least 95% of normal outbound CRM changes in any month and inbound Microsoft changes across the full 15-month scheduled set (current, adjacent, and 12 recent months at 200 items each) visible across calendars within 15 minutes; manual refresh success or clear failure within two minutes; and zero duplicate linked items after replay. Also verify initial import, two-minute delayed/failure feedback, Retry, and rate-limit status for an untracked month. Review 375px, 1366px, 2560px, 200% zoom, light/dark, keyboard, loading/empty/error states.

## 5. Deployment and recovery

Apply SQL before Edge and UI. If app permissions, scheduler dependencies, or provider calls fail, leave the connection inactive; the CRM-only calendar remains functional. To suspend a faulty release, disconnect the calendar, disable the named cron job, and roll back Edge/UI deployments. Do not delete existing Microsoft mirrors on disconnect. Keep additive tables and associations for audit and safe reconnection. The human operator handles all commit, push, tenant-consent, and production-deployment actions.
